# LAN Cache Architecture

This project is a lightweight local-area-network file cache and discovery service. It allows multiple machines on the same LAN to discover each other and share a common file set through a simple HTTP API.

## Project overview

The system is composed of two main parts:

1. A file-serving node that exposes files and metadata over HTTP.
2. A peer-discovery layer that uses UDP broadcast messages to find other nodes on the local network.

Both parts run inside the server folder and share the same local file repository located in the files folder.

## High-level architecture

```text
+---------------------+         UDP broadcast / response          +---------------------+
| Node A              | ----------------------------------------> | Node B              |
|                     |                                            |                     |
| Express API         |                                            | Express API         |
|   /files            |                                            |   /files            |
|   /api/files        |                                            |   /api/files        |
|   /api/peers        |                                            |   /api/peers        |
|                     |                                            |                     |
| files/             |                                            | files/              |
|   hello.txt        |                                            |   hello.txt        |
|   greeting.txt     |                                            |   greeting.txt      |
|   greeting2.txt    |                                            |   greeting2.txt     |
+---------------------+                                            +---------------------+
```

## Main components

### 1. File storage layer

The project keeps shared content under the files folder in the project root.

- Each file is served statically through Express.
- File metadata is generated by reading the file system and computing a SHA-256 hash.
- The API exposes:
  - file names
  - file size
  - hash value

This makes the system useful for cache validation and file consistency checks across peers.

### 2. HTTP service layer

The application in server/server.js is the main runtime service.

Responsibilities:

- Start an Express server on port 5000
- Serve files under /files
- Expose metadata at /api/files
- Expose discovered peers at /api/peers

Example API behavior:

- GET /files/<filename> returns the actual file content
- GET /api/files returns JSON containing all files and their metadata
- GET /api/peers returns the known peers found through discovery

### 3. Peer discovery layer

The discovery logic in server/discovery.js is built using Node.js UDP sockets.

- Port: 41234
- Protocol: UDP broadcast
- Messages:
  - LAN_CACHE_DISCOVERY
  - LAN_CACHE_RESPONSE

Flow:

1. A node starts and sends a discovery broadcast.
2. Other nodes on the same LAN receive the packet.
3. They verify the sender is not themselves.
4. They add the sender to a peer map and respond with a LAN_CACHE_RESPONSE.
5. The requester records responding peers and exposes them through /api/peers.

This allows the network to self-identify without a central registry or DNS service.

## Why this is a distributed LAN cache

The design is intentionally simple:

- every node stores a local file set
- nodes find each other automatically on the LAN
- file metadata is shared by HTTP
- peers are discovered dynamically through broadcast-based discovery

This gives the project a distributed caching style architecture, even though it is still a minimal proof-of-concept rather than a production-grade distributed system.

## Runtime responsibilities

### Server startup

The server starts by:

- creating the Express app
- binding the HTTP port
- registering the discovery process
- starting UDP discovery broadcasts

### Peer tracking

A Map is used to keep peer information such as:

- ip
- httpPort
- lastSeen

This allows the server to remember which devices are active and respond with peer status through the API.

## Typical usage

1. Install dependencies in the server folder.
2. Start the server:

```bash
cd server
npm install
npm start
```

3. Access the files through the mapped HTTP endpoints.
4. Use /api/peers to inspect other machines detected on the LAN.

## Limitations

This is a minimal local-network implementation and not a full distributed cache system. It does not yet include:

- persistent peer metadata storage
- file replication strategies
- cache invalidation policies
- authentication or authorization
- distributed consistency guarantees
- automatic failover or fault-tolerant leadership

## Summary

The architecture is a simple distributed cache pattern built around:

- local file storage
- UDP peer discovery
- Express-based file and peer APIs
- LAN-local metadata exchange

This makes it easy to extend into a broader caching or file-sharing service while keeping the initial implementation lightweight and understandable.
